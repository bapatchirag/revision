The screen is a left column of Status, Files and Log, beside a Main detail view with a
Command Log beneath it.

<AppScreen golden="TestModelGoldenLayout" />

Each panel carries its number in the top border — `[2] Files` — and the focused one is
drawn in the accent colour. The Command Log has no number; it is reached with
<KeyCap key="x" /> and the mouse. The frame also carries a position and count in the bottom
border (`1 of 3`) where a count makes sense.

| Panel | Key | What it shows |
|-------|-----|---------------|
| Status | <KeyCap key="1" /> | The working-copy root, the source path `revision` is operating on, the current directory, the branch, and the checked-out revision against HEAD. |
| Files | <KeyCap key="2" /> | Pending changes, as a directory tree, grouped by changelist, or as saved patches. |
| Log | <KeyCap key="3" /> | Revision history, newest first. An asterisk marks the revision the working copy sits at, and a dot any picked to be compared. |
| Command Log | <KeyCap key="x" /> | The `svn` actions `revision` has run on your behalf, newest first, each marked ✓ or ✗. |
| Main | <KeyCap key="0" /> | Detail for whatever is selected: a diff for a file or directory, metadata and changed paths for a revision. |

## Moving between panels

- <KeyCap key="1" />, <KeyCap key="2" />, <KeyCap key="3" />, <KeyCap key="0" /> — focus a panel directly.
- <KeyCap key="tab" /> / <KeyCap key="shift+tab" /> — cycle forwards and backwards through the
  side panels: Status, Files and Log. Main and the Command Log are outside the cycle, so
  <KeyCap key="tab" /> pressed on either returns to the side panel driving Main.
- <KeyCap key="x" /> — show or hide the Command Log. It has no number of its own, so
  clicking it is the only way to focus and scroll it.

With [`allowMouse`](/reference/configuration/#allowmouse) on, clicking a panel focuses it.

## Moving inside a panel

Every panel scrolls on both axes, with scrollbars that show how much is off-screen. With
the mouse on, the wheel scrolls whichever panel the pointer rests on, focused or not.

| Keys | Action |
|---|---|
| <KeyCap key="↑" /> <KeyCap key="k" /> · <KeyCap key="↓" /> <KeyCap key="j" /> | Move the selection up / down |
| <KeyCap key="g" /> · <KeyCap key="G" /> | Jump to the top / bottom of a list |
| <KeyCap key="K" /> · <KeyCap key="J" /> | Scroll the Main panel up / down a page |
| <KeyCap key="←" /> <KeyCap key="h" /> · <KeyCap key="→" /> <KeyCap key="l" /> | Scroll the focused panel one column left / right |
| <KeyCap key="Home" /> <KeyCap key="^" /> · <KeyCap key="End" /> <KeyCap key="$" /> | Jump to the start / end of the line |

## Status

Six rows, any of which is omitted when it has no value:

| Row | Meaning |
|---|---|
| `Root` | The working copy's root directory. <KeyCap key="W" /> [moves to another one](#switching-repositories) for the session. |
| `Source` | The directory the views are scoped to — the same as `Root` when [`displayFrom`](/reference/configuration/#displayfrom) is `root`. <KeyCap key="P" /> [moves it](#changing-the-source-path) for the session. |
| `CWD` | The directory `revision` was started in. |
| `Branch` | Derived from the repository URL: `trunk`, `branches/<name>` or `tags/<name>`. Blank when the repository does not follow that layout. |
| `Revision` | The revision the working copy sits at. |
| `HEAD` | The repository's latest revision, when it differs from `Revision`. |

### Changing the source path

<KeyCap key="P" /> moves `Source` anywhere inside `Root` for the rest of the session. The
prompt opens on the directory `revision` is reading now and lists what is under it: typing
narrows the list, <KeyCap key="tab" /> steps into it and back, and the parent directory
leads it so the list walks up as well as down. The working copy's root is fixed at the head
of the input — it cannot be deleted, and a path above it is refused — so the source never
leaves the checkout.

Everything is re-read for the new source — the trees, the history and the cached diffs are
dropped and fetched again — so the panels show that subtree and nothing else. The change is
never written to the config file; the next launch uses [`--path`](/reference/cli/#--path)
again.

### Switching repositories

<KeyCap key="P" /> stays inside `Root`; <KeyCap key="W" /> leaves it. The prompt lists the
working copies it can find in the directory `revision` was started in, in the checkout it
is reading, and in that checkout's parents a few levels up — so a sibling of your tree is
offered as readily as something inside it. They arrive nearest first, typing narrows the
list, and <KeyCap key="tab" /> steps into it and back.

Any checkout the search did not reach is opened by typing its path in full. `~` expands,
and a relative path is taken from the current source. The path is checked before anything
moves: if it is not a directory, or if `svn` does not recognise it as a working copy, the
switch is refused, the reason is shown, and the prompt reopens on what you typed so it can
be corrected.

A switch re-reads everything, exactly as changing the source path does, and it too lasts
for the session only.

:::note
The search runs in the background: the prompt opens immediately and the list fills in
behind it, so a slow or network filesystem delays the suggestions rather than the
keystroke. Each place it looks is covered in full before the next is started, nearest
first, so a slow directory above your checkout cannot crowd out the one you are standing
in. It stops at each checkout it finds, since everything under a working copy belongs to
it, and gives up after a few seconds rather than walking a large tree to the end. A working
copy served over `svn+ssh` needs its key already unlocked; if it is not, the check that
guards the switch fails as an authentication error and nothing changes.
:::

## Files

The Files panel has four views. <KeyCap key="[" /> and <KeyCap key="]" /> turn between
them, and the active one is named in the top border — where all four can be clicked, with
the mouse on.

### Changes

Pending changes as a collapsible directory tree, each change grouped under its folder.
<KeyCap key="enter" /> expands or collapses a directory. Each row is a marker, the SVN
status code (`A`, `M`, `D`, `?` …) and the file name. A green `●` marks a staged file and
a cyan `●` a file in a [named changelist](/workflows/changelists/); an unstaged file has no
marker.

The footer counts the position and the number of files in view. When a
[filter](/workflows/filtering-and-searching/),
[`hideUntracked`](/reference/configuration/#hideuntracked) or a
[hide rule](/reference/configuration/#hiderules) hides some, the full count
follows in brackets — `1 of 16 (29)`.

A row waiting on a revert, a delete or a commit is dimmed and tailed with `…`, and the
directories above it carry the count of what is in flight beneath them. Those rows are
inert until `svn` answers — see [rows in
flight](/workflows/staging-and-commit/#rows-in-flight).

A conflicted file (`C`) is resolved with <KeyCap key="m" />, which opens its conflicts
[side by side](/workflows/conflicts/).

### Changelists

The same changes bucketed by [changelist](/workflows/changelists/): named lists first,
then `(staged)`, then `(unstaged)`.

<AppScreen golden="TestChangelistsViewGolden" />

<KeyCap key="enter" /> drills into a list, which then owns the panel — the border names
it and <KeyCap key="esc" /> goes back.

### Diffs

Patches you have [saved with `w`](/workflows/diffs/#saving-a-diff), newest first, read
from [`diffOutputDir`](/reference/configuration/#diffoutputdir). Selecting one shows it in
Main; <KeyCap key="e" /> opens it in your [editor](/workflows/editor/),
<KeyCap key="p" /> [applies it](/workflows/diffs/#applying-a-saved-patch) to the working
copy, and <KeyCap key="d" /> deletes it from the store.

The rows are files, not working-copy changes: stage and revert do nothing here.

### Rejects

The `.rej` files left behind by a patch, found by walking the [source
path](#changing-the-source-path) recursively and laid out as the same tree as
Changes — <KeyCap key="enter" /> expands and collapses a directory. svn ignores rejects,
so this is the only view that shows them. Selecting one shows its contents in Main;
<KeyCap key="m" /> [resolves it](/workflows/conflicts/) against the file it was written
for, <KeyCap key="e" /> opens it in your [editor](/workflows/editor/) and
<KeyCap key="d" /> deletes it from disk. See
[Finding rejects](/workflows/diffs/#finding-rejects).

## Log

Revision history, newest first, a page at a time. Each row carries the full revision
number, the author, and the first line of the message. An asterisk marks where the working
copy sits.

Selecting a revision shows its date, full message and changed paths in Main.
<KeyCap key="space" /> [updates the working copy](/workflows/updating/) to the selected
revision.

<KeyCap key="v" /> picks a revision to compare, up to two at a time, and
<KeyCap key="enter" /> diffs them: the panel becomes a tree of the files they touched and
Main follows it like the Changes view. <KeyCap key="esc" /> comes back out. See
[Comparing revisions](/workflows/diffs/#comparing-revisions).

A page holds [`logLimit`](/reference/configuration/#loglimit) revisions — 100 by default.
<KeyCap key="n" /> loads the next page and <KeyCap key="p" /> the previous one. The footer
shows where the cursor sits within the page and which page you are on, so `12 of 100 · 3`
is the twelfth revision of the third page.

Filtering with <KeyCap key="/" /> searches the page on screen, not the whole history; the
filter stays applied as you turn pages. Drilled into a comparison it narrows the files
instead, and the revisions get their own filter back on the way out. Committing returns
the panel to the first page, so the new revision is in view.

## Command Log

Every `svn` command `revision` ran on your behalf, newest first, each marked ✓ or ✗.
Read-only queries — the status and log refreshes that happen constantly, including the
background ones — are left out, so the list stays a record of what actually changed.

Toggle the panel with <KeyCap key="x" />. It has no number and is not in the
<KeyCap key="tab" /> cycle, so click it to focus and scroll it.

## Main

Detail for the current selection, and the target of the
[search](/workflows/filtering-and-searching/), [side-by-side](/workflows/diffs/) and
[save-diff](/workflows/diffs/#saving-a-diff) actions.

| Selection | Main shows |
|---|---|
| A file | Its diff, colour-coded. |
| A directory | The combined diff of every change beneath it, when [`directoryDiff`](/reference/configuration/#directorydiff) is on. |
| A changelist | The combined diff of its members. |
| A saved patch | The patch file's contents. |
| A revision | Date, author, full message, and changed paths. |
| A file in a compared range | That file's section of the range's diff. |
| The Status panel | Project links and version information. |

A diff is fetched once and reused for the rest of the session, so stepping back to a file
you have already read costs no `svn` at all.

## Keeping up with the working copy

`revision` watches the working copy in the background, so a file saved in your editor, a
build, or an `svn` command run in another terminal reaches the Files panel and the diff on
screen within a couple of seconds. The cursor stays on the same file and Main keeps its
scroll position — a refresh you did not ask for never moves the screen under you.

Nothing is re-read while a prompt, the commit editor, the settings form, the help menu or
the side-by-side overlay owns the screen. The refresh is held and taken once the screen is
free, so closing a dialog costs exactly one reload.

<KeyCap key="L" /> turns the watcher off and on for the session;
[`liveRefresh`](/reference/configuration/#liverefresh) sets the default.
<KeyCap key="R" /> still re-reads status and history on demand, whether the watcher is
running or not.
